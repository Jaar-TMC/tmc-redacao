<objective>
Close PAG-04 gap: wire cursor tracking directly into RedacaoPage's existing useEffect data-fetching pattern. RedacaoPage currently calls `getArticles` directly — it does NOT use `useArticlesQuery`. Rather than migrating the entire data-fetching to TanStack Query (a large, risky change), this plan adds cursor state management to the existing pattern with minimal changes.

Purpose: Make the frontend actually send cursor params on sequential page navigation so keyset seek is triggered on the backend. Without this, the backend's cursor support (Plan 01) is unused in production.

Approach: Add a `cursorMapRef` (same pattern as useArticlesQuery), store `nextCursor`/`prevCursor` from responses, pass cursor to `getArticles` when navigating sequentially, reset on filter changes.
</objective>
